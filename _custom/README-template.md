# Import template `_custom/template.md`: maintainer notes

Notes for picking up work on the personal import template. They cover what
each part does, which plugin data it relies on, the rendering details that
cause surprises, and what is still open.

Related: [README-open-in-zotero-reader.md](README-open-in-zotero-reader.md)
(why the Zotero reader links look the way they do) and [README.md](README.md)
(how the plugin talks to Zotero).

Original version, before the reader links were added: saved only in a
temporary scratchpad (not in git). `_custom/` is untracked, so **commit or
back up this folder** before making bigger changes.

---

## 1. How the template is used

- Configured in plugin settings → **Import formats** → *Template file*. The
  path is **vault-relative**. The loader (`ObsidianMarkdownLoader`,
  `src/bbt/template.env.ts`) resolves it with
  `app.metadataCache.getFirstLinkpathDest`, so the file must be **inside the
  vault**. `_custom/template.md` in this repo is the source copy. Copy or
  symlink it into the vault, and keep the two in sync.
- Rendered by **Nunjucks 3.2.4** with `autoescape: false`. URLs, `&` and HTML
  are written as is, with no `&amp;`.
- Rendered once per item, with the item's data (section 3) as the context.
- The template is only re-read at import time, so changes take effect on the
  next import. No reload is needed.

## 4. Link recipes used (and why)

```nunjucks
{# reader link for an attachment: PDF, EPUB, snapshot, upper-case .PDF #}
{{ att.pdfURI or (att.desktopURI | replace("zotero://select", "zotero://open-pdf")) }}

{# native annotation: jump to the annotation (page as an extra hint if known) #}
{{base}}?{% if a.page %}page={{a.page}}&{% endif %}annotation={{a.id}}

{# PDF-embedded annotation: page only #}
{{base}}{% if a.page %}?page={{a.page}}{% endif %}
```

- `open-pdf` only accepts an **attachment** key, never the parent item. The
  `select` → `open-pdf` replace works because both links have the same path.
- `page=` must be the **physical** page (Zotero uses `pageIndex = page - 1`).
  That's why the template uses `a.page`, and `a.pageLabel` only as the visible
  link text.
- Links go stale when an attachment is deleted or replaced in Zotero. Fix:
  re-import (frontmatter and `[!LINK]` refresh at once; annotations, see
  section 5).

## 5. Rendering behaviour that is easy to get wrong

### `persist` blocks and the import-date marker

- `{% persist "id" %}…{% endpersist %}` renders as
  `%% begin id %%<kept content><new content>%% end id %%`
  (`PersistExtension`, `template.env.ts:148`). On re-import, everything that
  was between the markers is **kept as is** and the newly rendered body is
  **appended**. Nothing inside is re-rendered.
  → Template changes inside the annotations block only affect annotations
  imported **after** the change. To rebuild, delete the content between the
  markers and re-import. Manual edits there are lost.
- Everything **outside** `persist` blocks is overwritten on every import.
- When the output contains a persist block, the plugin appends
  `%% Import Date: <ISO> %%` as the **very last line** of the file
  (`appendExportDate`, `template.helpers.ts:68`).
  `getLastExport` only finds it if it is exactly at the end of the file
  (`/…%%\n$/`). **If anything is written after that line** (manual text,
  another plugin), `lastImportDate` falls back to 1970, and **all annotations
  are appended again (duplicates)**.
- `newAnnotations` = `annotations | filterby("date", "dateafter", lastImportDate)`.
  For native annotations, `date` is `dateModified`, so **editing an annotation
  in Zotero makes it "new" again** and it gets appended a second time.

### Nunjucks whitespace control

- The frontmatter must start at **byte 0** with `---`. Don't put tags,
  comments or macros above it, unless they use `{%- … -%}` / `{#- … -#}` and
  you've confirmed the output.
- `{%-` / `-%}` strip *whitespace* only, not `>`. Lines like
  `> {%- for … %}` keep the `>`. That's why the `[!LINK]` callout contains an
  empty `>` line.
- Macros are defined when the renderer reaches them, not hoisted. Define a
  macro **before** its first use (e.g. don't use macros in the frontmatter
  unless they are defined above it).
- The trailing `.` after `[!LINK]`, `[!Abstract]` and `# Notes` are artefacts
  of `-%}.` in the original template. Harmless, but they show up as a lone
  `.` in the note.

### Filters available

| Filter | Source | Notes |
| --- | --- | --- |
| Nunjucks built-ins (`first`, `selectattr`, `groupby`, `replace`, `capitalize`, …) | Nunjucks | `selectattr` only supports the **one-argument** (truthy) form |
| `filterby(prop, cmd, …vals)` | `template.env.ts:68` | `startswith` / `endswith` / `contains` (**case-insensitive**), `dateafter` / `dateonorafter` / `datebefore` / `dateonorbefore` (moment values) |
| `format("YYYY")` | `template.env.ts` | moment format. Returns the input unchanged if it isn't a date |
| `setAttribute(key, value)` | `template.env.ts:277` | mutate a dict inside a template |

Note the mismatch: `filterby("path", "endswith", ".pdf")` is
case-insensitive, but `pdfURI` is only set for lowercase `.pdf`. The `or`
fallback in the reader-link recipe covers this.

## 7. Test checklist after changing the template

1. Data explorer on a test item: no render error, fields as expected.
2. Import an item **with no attachments**: frontmatter is valid YAML, no
   `zotero-reader` key, `[!LINK]` only shows "Show in Zotero".
3. Import a PDF item with **native** annotations: each annotation link opens
   the reader and selects the highlight. Test one on page 1.
4. Import a PDF with **embedded** annotations: the link opens at the right
   physical page.
5. Import an **EPUB** or snapshot item: `zotero-reader` and the annotation
   links open Zotero's reader.
6. Re-import the same item: no duplicate annotations, and the
   `%% Import Date … %%` line is still last.
7. Open the note in a Canvas file card and click a reader link.
